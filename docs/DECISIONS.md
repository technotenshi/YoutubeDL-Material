## 2026-10-12 Harden and speed up the Docker build (#12)

- Every fetched input now resolves to a version recorded in the repository. `docker-utils/twitchdownloader.env` holds the TwitchDownloaderCLI version (1.56.5) and a sha256 per architecture, and `fetch-twitchdownloader.sh` reads it, verifies the download with `sha256sum -c`, and exits on a mismatch. The release lookup (and `jq`) is gone. #41 can source the same file. The digests are the ones GitHub publishes per asset (trust on first use); all three zips were downloaded and hashed to confirm they match.

This exposed that `TwitchDownloaderCLI --help` and `version` both exit 1, so the old smoke test could never have been checked by exit code. ## 2026-10-13 Declare least-privilege permissions in every workflow (#35)

- Every workflow now declares its own `GITHUB_TOKEN` permissions instead of inheriting the repository default (read and write). The baseline is `contents: read` at workflow level. Job-level `permissions` replace the workflow-level block entirely, so a job that needs more restates `contents: read` next to its extra grant.
- Grants beyond read, and why: `build.yml` release job has `contents: write` to create the draft release and upload the zip; `codeql-analysis.yml` analyze job has `security-events: write` to upload results to code scanning; the `docker.yml` and `docker-release.yml` publish jobs have `packages: write` to push to ghcr.io. - `close-issue-if-noresponse.yml` declares only `issues: write` and no `contents: read`. It makes API calls and has no checkout step, so it needs no repository contents grant. This differs from the ticket's read baseline on purpose.
- `actions: read` is not added to CodeQL because the repository is public. Artifact upload and download, `actions/cache` and the `type=gha` Buildx cache use the runner's own runtime token, not `GITHUB_TOKEN`, so they need no grant.
- Verified locally with a throwaway `yq` check: before the change six workflows had no top-level `permissions`; after it every workflow declares one and the only effective write grants are the five listed above. `git diff --check` is clean.
